How this is supposed to work

The user keeps their normal Roblox account. Orbio is an additional account connection used by the ROBLIO app to authorize model/tool usage on the user's Orbio balance.

01 / CONNECT

Connect Orbio

On the ROBLIO web app, the player chooses “Sign in with Orbio” and approves the requested scopes.

ROBLIO → Orbio OAuth 2.1 + PKCE → callback
02 / ENTER

Join Roblox

The player still launches Roblox and enters the ROBLIO experience with their normal Roblox account.

Web session ↔ short-lived pairing code ↔ Roblox join
03 / INTERACT

Play with Orbio

The Roblox server sends a game event to the ROBLIO backend. The backend calls Orbio and returns the result to the game.

Roblox server → ROBLIO backend → Orbio API → Roblox

The technical loop

For the first MVP, keep the chain simple. No keys in browser code. No Orbio access tokens passed through Roblox launch data.

1. OrbioOAuth connection creates a player session.
2. ROBLIOYour backend stores the secure session and pairing state.
3. RobloxPlayer joins using their normal Roblox account.
4. BackendRoblox server calls your API over HttpService.
5. Orbio APIYour backend calls the model using the user's Orbio access token.

Documentation / disclaimer

This section exists so visitors understand what is real, what is planned, and what this one-file prototype is demonstrating.

ORBIO
Sign in with Orbio

Orbio documents OAuth 2.1 + PKCE. A server app can exchange the authorization code for an access + refresh token and call the Orbio API on the user's balance.

API
Server-side only

Orbio's docs state that the gateway is called from the app/server, not directly from a web page. Tokens should stay off the client.

ROBLOX
Roblox identity stays Roblox

The player still signs into Roblox normally. ROBLIO adds an Orbio connection; it does not replace the Roblox account.

ROBLOX
Launch data is not a secret

Roblox launch data can help pair a join with a session, but it is visible and user-modifiable. Use a short-lived, server-validated pairing code instead of sending credentials.

IMPORTANT — this is a static front-end demo

No real authentication happens in this single HTML file. The “Connect Orbio” button below only demonstrates the UI state. A production version needs a backend for OAuth callback handling, token storage/refresh, session pairing, Roblox server authentication, and the Orbio API call.

What gets added next

1) Register a ROBLIO app in Orbio. 2) Add OAuth callback + PKCE on your backend. 3) Create the Roblox experience. 4) Pair a Roblox player with a short-lived ROBLIO session. 5) Let the Roblox server call your backend. 6) Let your backend call Orbio.
