How this is supposed to work

simple on the outside / secure on the inside

The user still has a normal Roblox account. Orbio becomes an additional account connection for the ROBLIO app, so the game can associate the player's session with Orbio-backed AI functionality.

01 / CONNECT

Connect Orbio

On the ROBLIO web app, a player signs in with Orbio and approves the scopes that the real product will need.

ROBLIO → Orbio OAuth 2.1 + PKCE → callback
02 / ENTER

Join Roblox

The same person launches Roblox and joins the ROBLIO experience using their normal Roblox identity.

web session ↔ short-lived pairing code ↔ Roblox join
03 / INTERACT

Play with Orbio

The Roblox server sends a game event to the ROBLIO backend. The backend can then call Orbio and return the result to the game.

Roblox server → backend → Orbio API → Roblox

The technical loop

what happens behind the glass

For the minimal demo, keep the chain simple. No secret in browser code. No Orbio token inside Roblox launch data. Use the backend as the secure bridge.

01 / ORBIO
ConnectOAuth creates the web session and authorizes the approved scopes.
02 / ROBLIO
PairThe backend creates a short-lived pairing code for the Roblox join.
03 / ROBLOX
JoinThe player enters the real Roblox experience with their normal identity.
04 / SERVER
EventRoblox server calls your backend through HttpService.
05 / API
RespondYour backend calls Orbio and returns the result to the game.

Documentation / disclaimer

tap a row to inspect the idea

This page separates the experience we want to show people from the infrastructure that still needs to be connected in the production build.

O Sign in with Orbio⌄
The intended flow is an Orbio OAuth connection handled by the ROBLIO backend. The browser should not store the Orbio client secret or call the gateway directly.
ROBLIO → Orbio OAuth → callback → secure server session
R Roblox account stays separate⌄
Players still authenticate with Roblox in the normal way. ROBLIO adds an Orbio connection on top of that. The concept is a two-account experience: Roblox for the game identity, Orbio for the connected AI account.
↔ Pairing the two sessions⌄
The web app can issue a short-lived pairing code. Roblox can receive launch data, but that data is not a secret. The Roblox server should validate the pairing with the ROBLIO backend before associating the player with the web session.
web session ↔ short-lived code ↔ Roblox server
AI Orbio inside the game⌄
Once paired, a Roblox server event can hit your backend. The backend can then call Orbio's server-side API and return a compact response that the game displays as an NPC line, event, judge, quest, or other mechanic.
! Prototype disclaimer⌄
The current site has a real Orbio OAuth connection when deployed with the included Vercel backend. The buttons demonstrate the intended state changes only. A real launch requires an Orbio app, OAuth callback, backend token handling, Roblox experience, pairing endpoint, and Roblox server code. ROBLIO is not an official Roblox or Orbio product unless separately announced.
